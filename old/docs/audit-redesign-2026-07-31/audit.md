# Clipline 产品与界面审计

审计日期：2026-07-31
审计范围：真实代码、运行中的前后端、核心页面与主要工作流。

## 产品结论

Clipline 不是实时摄像头或 NVR 管理系统。它是部署在 NAS 或家庭服务器上的“录像文件工作台”：

1. 把 NAS、本地硬盘中的录像目录添加为录像源。
2. 扫描目录，使用 FFmpeg / ffprobe 建立片段索引和缩略图。
3. 将按分钟切分的文件映射到真实时间轴，显示录像区间与断档。
4. 连续回放片段，按真实时间定位。
5. 选择一段真实时间范围，跨文件快速或精准导出。
6. 对片段执行语音识别与视觉识别，用字幕或标签检索片段。
7. 在任务中心查看导出、语音识别和视觉识别的状态。

录像源的本质是“允许扫描的文件目录”，不是 RTSP 连接，也不包含实时网络延迟、码流管理、录像计划或摄像头在线监控。

## 当前功能清单

### 录像源与扫描

- 新建、编辑、删除录像源。
- 从允许访问的录像根目录中选择路径。
- 启用或停用录像源。
- 手动扫描。
- 配置 5、15、30、60 分钟的定时扫描。
- 查看总片段数、失败数、最近扫描和扫描任务状态。
- 跳过仍在写入的新文件。
- 为每个录像源配置自动语音/视觉识别策略。

### 回看与时间线

- 按录像源、日期范围加载片段。
- 显示真实时间轴、录像区间和断档。
- 点击片段或有录像时间点进行定位。
- 播放结束后切换到后续片段。
- 调整时间轴缩放。
- 查看缩略图片段墙。
- 以真实时间区间创建导出。

### 片段库

- 网格和列表视图。
- 按日期筛选。
- 按视觉识别标签筛选。
- 按字幕文字搜索。
- 查看片段时长、缩略图、识别状态和标签。
- 打开片段详情并返回回看。
- 创建语音识别、视觉识别和导出任务。

### 搜索与识别

- 语音识别字幕全文检索。
- 搜索建议和热门词。
- 点击搜索结果定位到片段时间。
- 导出 SRT 或 TXT 字幕。
- 视觉识别人、猫、狗、车辆、电话机等标签。
- 查看片段视觉识别结果和置信度。

### 任务

- 导出任务。
- 语音识别任务。
- 视觉识别任务。
- queued、running/processing、completed、failed 等状态。
- 进度、结果、失败原因和批量创建。
- 导出完成后下载。

### 日志与系统

- 手动扫描日志。
- 定时扫描日志。
- 导出任务记录。
- 扫描失败片段及错误信息。
- 预留语音识别、登录审计和源配置变更分类。
- 系统状态：FFmpeg、ffprobe、数据库、录像根目录、日志文件。

### 设置

- 系统状态概览。
- 扫描与索引默认值。
- 导出、缓存、保留时长、最大时长和并发设置。
- 语音识别模型、语言、设备与并发配置。
- 视觉/识别任务默认配置。
- 日志级别、格式与文件位置。
- 版本与系统信息。

## 核心用户工作流

### 工作流 A：首次建立录像索引

添加录像源 → 选择挂载目录 → 创建并扫描 → 查看扫描进度 → 片段进入索引。

### 工作流 B：定位并导出录像

选择录像源 → 选择日期 → 在时间轴或片段列表定位 → 播放确认 → 选择真实时间范围 → 选择快速/精准模式 → 创建导出任务 → 下载。

### 工作流 C：通过内容查找录像

对片段创建语音或视觉识别任务 → 等待任务完成 → 搜索字幕或筛选标签 → 打开结果 → 定位回看或导出。

### 工作流 D：维护数据处理

查看任务中心 → 处理失败任务 → 查看扫描/导出错误 → 调整录像源扫描策略或全局设置。

## 当前界面审计

### Step 1：回看页

证据：`01-playback.png`、`07-segment-selected.png`
健康度：需重构。

优点：

- 播放器、时间轴和片段墙放在同一工作区。
- 录像源、日期、缩放和上下片段操作齐全。
- 能表达片段与断档。

问题：

- 时间轴竖向放置，占据固定宽度，但时间信息密度低，与横向视频播放习惯冲突。
- 播放器、控制面板和片段墙之间缺少清晰的主次关系。
- 导出入口和导出区间不够显眼，核心任务需要寻找。
- 日期范围与单日回看混在同一控制层，认知成本较高。
- 片段选择后，播放器反馈不足，空态和加载/不支持状态不容易区分。

### Step 2：片段墙

证据：`02-clips.png`
健康度：功能完整，密度过高。

优点：

- 日期、标签、字幕三个检索维度符合产品能力。
- 缩略图、时长、识别标签和时间信息可直接比较。
- 网格/列表切换清晰。

问题：

- 左侧筛选项过长，常用筛选与高级筛选没有分层。
- 卡片缺少明显的识别状态、处理入口和选择状态。
- 大量相似缩略图连续出现时，不容易判断片段差异。
- 缺少选中片段的稳定详情区，操作容易依赖悬浮或抽屉。

### Step 3：任务中心

证据：`03-tasks.png`
健康度：数据模型正确，层级重复。

优点：

- 正确覆盖导出、语音和视觉三类任务。
- 任务状态、进度和结果都能看到。
- 支持批量创建识别任务。

问题：

- 页面标题、模块标题、统计卡、类型筛选、状态筛选层级重复。
- “待处理”同时包含未创建任务，和后台 queued 的含义容易混淆。
- 文件名过长，压缩了真正重要的来源、时间、状态和结果。
- 任务创建按钮与任务列表上下文距离较远。

### Step 4：录像源

证据：`04-sources.png`
健康度：业务逻辑正确，信息组织可简化。

优点：

- 正确使用目录路径、启用/停用、扫描策略和片段统计。
- 识别配置放在单个录像源下，符合覆盖全局默认值的模型。
- 手动扫描入口明确。

问题：

- 顶部四个统计卡与下方选中源信息重复。
- 单源场景中左侧列表占用较大空间。
- 基础信息、运行状态、片段统计和识别配置卡片过多。
- 危险操作、扫描操作和编辑操作缺少文字说明。

### Step 5：日志

证据：`05-logs.png`
健康度：业务正确，空内容占比过大。

优点：

- 日志来源与真实业务一致：扫描、导出、错误。
- 扫描日志包含扫描数、入库数、失败数。
- 分类清楚。

问题：

- 顶部统计卡与左侧分类重复。
- 只有一条记录时，界面仍保留大量仪表盘结构。
- 登录日志、源变更、语音识别属于预留分类，容易让用户误以为已经完整实现。
- 日志适合做紧凑的可筛选活动表，而不是主导航中的高频工作区。

### Step 6：设置

证据：`06-settings.png`
健康度：结构清晰，可继续收敛。

优点：

- 设置分类与实际后端能力一致。
- 系统路径、FFmpeg 和缓存信息对 NAS 部署排障很有价值。
- 识别和任务设置有独立入口。

问题：

- 概览页的卡片、路径和版本信息层次松散。
- 技术字段缺少“何时需要修改”的解释。
- 设置和录像源的识别配置之间需要更明确的“全局默认/单源覆盖”关系。

## 重新设计的信息架构

### 一级导航

1. 回看
2. 片段库
3. 任务
4. 管理

全局搜索保留在顶部，只用于搜索真实字幕或片段内容，不作为独立菜单。

### 管理二级导航

1. 录像源
2. 活动日志
3. 设置

### 设计原则

- 回看页围绕“找到时间 → 确认内容 → 选择区间 → 导出”组织。
- 默认时间线只显示真实片段和断档，不虚构人车事件轨。
- 识别结果作为片段属性、搜索结果或可选标记层出现。
- 录像源统一使用目录、扫描和索引语言，不使用在线、RTSP、直播或延迟语言。
- 日志只展示扫描、导出、识别和文件错误等可追溯事件。
- 设置明确区分全局默认与单源覆盖。
