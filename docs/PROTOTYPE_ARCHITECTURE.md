# Clipline 原型结构与二期接入

本文件记录保留的交互原型，对应 `DemoApp.jsx` 和显式 `?mode=demo`。D3 起默认 `App.jsx` 使用真实 API，接入契约与验证见 [开发文档](DEVELOPMENT.md)及 [D3 记录](qa/D3_PLAYBACK.md)。

## 新方案

本次重新设计由 `frontend/` 独立承载，保留原产品的目录扫描、真实时间回看和区间导出流程。旧文档中“必须完全对齐 full redesign”和“一期包含识别”的要求不适用于这版新原型。

界面沿用旧版的蓝色主题（`#087bfa`）、浅灰背景与白色内容面板，使用系统字体和同一套 Phosphor 图标。桌面使用完整侧栏，手机使用抽屉导航。回看页沿用旧版 UniFi 风格：左侧竖向时间轴，时间从上往下递减；日期、时段、缩放在时间轴顶部，播放器下方展示紧凑片段条。点击“管理片段”展开截取表单，直接拖动时间轴的起止边界或输入时间后导出。任务中心展示后台进度，独立日志中心记录过程与异常。

录像源切换统一放在左侧 Logo 下方的下拉列表中，下方显示片段数量与启用状态。选择录像源会进入对应源的回看页；播放器顶部只显示当前源名称。手机在导航抽屉中提供同一入口，选中后关闭抽屉。

添加录像源时先选择目录或手动输入路径，再确认自动建议的名称与扫描频率。目录浏览是明确标注的静态示例目录，已添加目录不可再次选择；用户手动改过名称后，换目录不覆盖名称。路径归一化、目录重复与边界检查由 `validateSourcePath` 同时用于添加和编辑流程，真实目录存在性和可读性仍需服务端确认。默认勾选首次扫描，添加成功后直接提交新源的扫描演示任务，切到录像源页并更新左侧选择；也可取消勾选，仅保存配置。新源尚无片段时展示空态，不套用示例录像画面。

点击视频画面、片段卡片或时间轴录像会展开右侧片段详情，切换片段时信息同步更新。详情包含录像时间、编码、分辨率、大小、文件名与源目录，可直接导出当前片段或转入时间轴截取。桌面并排展示，1180px 及以下使用可关闭的右侧模态抽屉；详情和区间管理按需切换。

视频元素按片段 ID 重建，即使多个演示片段共用同一个媒体地址，切换日期或片段也会应用正确的播放位置。从详情进入截取会以该片段的完整起止时间初始化范围；自动续播仍保留用户已编辑的截取区间。

| `src/pages/Tasks.jsx` | 按任务状态和类型呈现任务、进度及结果 |
| `src/pages/Logs.jsx` | 事件筛选、日志详情、任务关联与 JSON 导出 |
| `src/pages/Sources.jsx` | 目录配置、启停和扫描入口 |
| `src/pages/Settings.jsx` | 全局设置、关于与二期规划 |

| `src/capabilities.js` | 能力开关、扩展注册表和扩展位置 |

目录和文件是不同实体；片段始终有稳定 `id`、`sourceId`、`date`、`start`、`end`。`start/end` 在本原型中是北京时间当天的秒数。播放位置为 `clip.start + video.currentTime`。正式接入应改成带时区的 ISO 时间或 UTC 时间戳，避免跨日区间混淆。

`summarizeRange` 按半开区间 `[start, end)` 合并实际覆盖，不重复计算重叠文件。无录像的区间单独计入 `gap`。用户手动修改导出范围后，自动续播不覆盖已选择的范围。当前合并导出限定为同源同日，可自然扩展到正式后端的跨文件任务。

## 设置与草稿

设置按基础、扫描、回看、导出、后台任务、识别与模型、关于分类。`SETTINGS_FIELDS` 定义一期可编辑分类的字段边界，`mergeSettingsGroup` 仅更新选中分类，保存、撤销和恢复默认都不会带入其他分类草稿。草稿由 App 持有，切换分类或离开设置页仍保留；刷新后恢复已保存值，未保存草稿不写入 localStorage。导航圆点和总待保存数提示修改位置。

新源默认扫描间隔、回看连续播放、导出模式/最长范围和后台并行数会在当前原型生效；文件写入保护和定时扫描仅保存配置，需正式后端执行。关闭自动续播时断档偏好保留但控件暂不可操作。存储路径和固定北京时间为只读信息。二期模型、识别策略、运行设备与缓存只显示占位，不提供真实设置动作。系统设置日志标明实际改变的配置项。

## 后台任务与日志

一期规划四类耗时任务：目录扫描（发现文件、读取元数据、更新索引和缩略图）、录像导出（裁剪、拼接、必要转码）、索引重建（修复或重新校验索引）、播放准备（不兼容视频的播放代理与缩略图缓存）。元数据和缩略图处理作为扫描/准备的阶段，避免每个文件产生一个独立顶层任务。普通筛选、查看详情和保存配置即时完成。

回看与片段库提交导出；任务中心可选择启用的录像源提交其余三类演示任务。同源同类处理中任务避免重复提交，任务复用并行队列，可取消、重新提交或失败重试。识别任务继续仅预留。

原型队列运行在 App 层，切换页面不阻塞；关闭浏览器页面会暂停。正式版需将任务持久化并交由服务端 worker 执行，重启恢复、断点续作和资源锁也应在服务端实现。索引重建与播放准备目前无真实处理 API 适配，不能仅凭演示进度认为底层操作完成。

日志中心从设置独立出来。新增记录带 `createdAt`（ISO）、`level`、`kind`、可选 `sourceId/taskId`、标题和详情；兼容旧原型只有时间文案的记录，缺省级别为信息。任务状态或阶段改变时产生记录，不按每次进度百分比重复写日志；配置变更也写入日志。支持类型、级别、源、关键词筛选及关联任务互跳。导出日志只包含当前筛选结果；诊断 JSON 包含本地设置、源和全部日志。日志目前保存在浏览器中，正式版对接服务端日志并补充保留策略。

## 二期能力开关与扩展位置

`PHASE_ONE_CAPABILITIES` 中 `transcription`、`visualRecognition`、`semanticSearch` 全部关闭。注册表拒绝注册未启用能力；一期不导入模型或识别模块，不发送识别请求，不展示灰色识别操作。

未注册扩展时，详情、搜索、任务和设置显示静态「二期预留」区域。字幕、画面识别结果与事件时间点统一预留在详情里；时间轴不显示识别占位，仅在代码中保留 `timeline-track` 扩展插槽。搜索预留内容搜索，任务中心预留识别任务，设置提供「识别与模型 · 二期」分类。占位中没有操作按钮、输入框、识别结果或模拟识别任务。二期注册真实组件后，同一插槽自动替换占位。

片段库一期查询只使用录像源、日期、文件名和起止时间，移除编码筛选。关键词会去除两端空白、忽略大小写并将中文冒号转换为英文冒号；时间为起止时刻的文本匹配，例如 `09:16:12` 同时匹配以此时刻开始或结束的片段，不作为时间区间查询。工具栏下方的 `library-filters` 插槽预留字幕搜索、画面标签及识别状态，当前不提供对应查询操作。

添加与编辑录像源提供 `source-settings` 静态占位，预留新录像语音转写、画面识别的手动/扫描后自动策略。保留与旧版相同的 `autoTranscribe`、`autoDetect` 字段，新源与缺省数据均为 false；当前没有可操作的识别开关。二期应同时检查全局能力和源策略，在扫描确认片段可处理后再提交识别任务，结果仍归片段详情。仅勾选首次扫描不会产生识别任务。

二期组件通过 `extensionRegistry.register({ id, capability, slot, component })` 注册，启动时提供启用后的能力配置。`component` 接收 `context`，可访问所在页面的片段、来源、当前时间或搜索查询。

| 扩展位置 | 已接入的位置 | 二期用途 |
| --- | --- | --- |
| `clip-detail` | 回看右栏、片段库详情 | 字幕、画面识别结果、手动触发识别 |
| `timeline-track` | 录像时间线内的扩展位置，一期不显示占位 | 二期有真实数据时可提供事件定位标记；详细识别结果在片段详情查看 |
| `task-type` | 任务中心 | 识别任务详情与类型专用动作 |
| `settings-section` | 设置的「识别与模型」分类 | 模型、识别默认策略与任务资源配置 |
| `search-provider` | 全局搜索弹窗 | 字幕与画面标签的搜索结果 |
| `library-filters` | 片段库查询工具栏下方 | 字幕搜索、画面标签及识别状态查询组件 |
| `source-settings` | 添加录像源与编辑录像源表单 | 按源配置语音转写、画面识别的触发策略 |

二期只打开开关还不会产生识别功能；须实现对应 provider、组件和后端适配。注册表是可工作的挂载边界，不是识别实现。

## 二期数据约定

识别结果通过 `clipId` 关联已有片段，不改变基础片段索引。一个结果建议保留以下字段：

```ts
type AnalysisResult = {
  id: string;
  clipId: string;
  kind: 'transcription' | 'visual';
  startOffsetMs: number;
  endOffsetMs: number;
  text?: string;
  labels?: { name: string; confidence: number }[];
  modelId: string;
  modelVersion: string;
};

type BackgroundTask = {
  id: string;
  kind: 'scan' | 'export' | 'reindex' | 'prepare' | 'transcription' | 'visual';
  sourceId: string;
  clipIds?: string[];
  status: 'queued' | 'running' | 'completed' | 'failed' | 'cancelled';
  progress: number;
  error?: string;
  result?: { kind: string; resourceId: string };
};
```

识别时间偏移是相对片段开头的毫秒数。点击搜索结果时，用片段真实开始时间加偏移定位，不将内容识别事件写入录像覆盖轨。识别失败不影响播放、目录索引或基础导出。任务类型标签、状态和结果动作应改为 provider 配置驱动，复用现有任务页骨架。

## 正式版 API 接入顺序

以下接口已在 `old/backend/app/api.py` 中存在；路径前缀与 schema 应以旧后端配置为准，原型目前未调用这些接口。

1. 用 `/sources`、`/recording-directories` 和 `/sources/{source_id}/scan` 替换本地录像源与扫描演示。真实目录权限、存在性与边界必须在服务端检查。
2. 用 `/segments`、`/timeline`、`/segments/{segment_id}/stream` 与 `/segments/{segment_id}/thumbnail` 替换示例目录和视频。视频的 Range 请求与浏览器编码能力保留。
3. 用 `/exports`、`/exports/{export_id}` 与 `/exports/{export_id}/download` 替换演示任务和固定下载文件。服务端实际裁剪、处理断档、跨文件拼接与临时文件清理。
4. 用 `/settings`、`/system/status`、`/system/logs` 替换本地设置与日志。将 export/scan 接口状态统一映射到任务视图。
5. 二期再适配 `/segments/{segment_id}/transcribe`、`/segments/{segment_id}/vision`、对应 job/result 接口及 `/search`。能力开关应由后端可用性与设置共同决定；模型配置通过设置扩展接入。

建议用独立 service adapter 隔离 API 字段与 UI 数据结构。基础功能接入完成后，再加载识别 provider，避免主流程依赖二期模型。

## 验收边界

- 当前交付为前端原型，不能用于真实目录扫描或证据区间导出。
- 播放、日期切换、筛选、区间计算、弹窗、配置保存及下载示例可实际操作。
- 二期插槽实际存在且受能力开关控制，有测试验证一期拒绝加载识别扩展。
- 原型只读复用旧版资产；没有修改 `old` 内的后端或前端。
