# D2：持久化队列与真实录像索引验证

日期：2026-10-13。版本：0.3.0。分支：`codex/phase-one-backend`。

## 实现边界

已实现源创建/编辑/启停、原子首次扫描、幂等请求别名、任务提交/查询/取消/重试、Worker 独占协调、源锁与媒体槽、调度、故障恢复、FFprobe 元数据、首帧缩略图、增量扫描与重建，以及片段/基础日志查询。API 使用 `/api`，真实交互可通过本地 `/docs` 操作。

统一模型保留四类任务；本阶段只执行 scan/reindex。prepare 的提交返回能力未接入，export 和识别提交拒绝；同规格 prepare 去重在 D3-05 实现，导出在 D4 实现。当前页面仍是交互原型，尚未调用这些真实 API；不将原型的模拟播放/导出计入正式能力。日志级别/关键词筛选、完整导出、SSE、配置写入及清理策略在 D5。

二期能力保持 false，不下载或初始化识别模型，不生成字幕、标签或识别结果。源策略只接受关闭值。

## 指定目录的真实验证

使用 `/Volumes/extended/clipline:ro` → `/recordings`；仅选择 media 下的真实录像目录。新 SQLite、缩略图、日志和临时文件写入项目 `data/local-test` → `/app/data`。原目录中的旧 DB、models、exports 和代理不导入。测试输出及设备目录标识不提交到仓库。

原生 ARM64 容器 `clipline-phase-one-clipline-1`，接口 `127.0.0.1:8088`，执行：

```bash
python3 deploy/smoke_indexing.py --restart
```

| 场景 | 实测结果 |
| --- | --- |
| 数据集 | 123 个 MP4，合计 16,508,780,544 字节；HEVC/Opus，3840×2160 |
| 首次完成扫描 | 123 个可用片段、123 张 JPEG；探测/缩略图失败均 0 |
| 时间来源 | 123 个均为文件名解析，源时区 Asia/Shanghai，存储 UTC；置信度 0.95 |
| 增量扫描 | 123 个全部复用；新增、更新、缩略图生成均 0 |
| 运行取消 | 实际 reindex 停止后为 cancelled |
| 用户重试 | 新 taskId 关联原取消任务，历史保留 |
| 强制结束 Worker | 处理中 SIGKILL；runtime 回收媒体组，Docker 重启服务；旧尝试 interrupted，新尝试完成 |
| 恢复复用 | attemptNo=2，recoveryCount=1；复用已完成 2 个，重新处理 121 个 |
| 索引稳定性 | 恢复前后 123 个片段 ID 完全一致 |
| 存储保护 | Docker inspect 验证录像映射 RW=false，新数据映射 RW=true |

首次完成扫描的统计为新增 114、更新 9，是此前本地开发停机留下的部分索引；合计处理 123，并非丢失文件。重建恢复按逻辑 taskId 复用，leaseToken 只负责每次尝试的写入隔离。

真实 HEVC 样本中点 seek 曾触发缩略图超时；现取首个视频帧并使用版本化 thumbnail profile。旧 profile 标记 stale，避免增量错误复用；最终真实扫描无超时。

amd64 镜像在本机 Docker 的架构模拟环境中使用独立 `data/d2-amd64` 和端口 8089 执行相同 `--restart` 流程：首次新增 123，缩略图 123，全部失败统计为 0；增量复用 123；取消/新 ID 重试/强制重启通过，恢复复用 2、重处理 121，attemptNo=2，片段 ID 一致。验证后移除该临时容器，保留忽略目录中的证据；8088 的原生 ARM64 本地服务继续运行。本结果不等于原生 x86 NAS 性能或发布验收。
