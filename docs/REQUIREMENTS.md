# Clipline 方案与需求文档

更新：2026-10-27 · 状态：一期需求与交付范围；仓库版本见根目录 `version.txt`

配套文档：[开发文档](DEVELOPMENT.md)、[开发任务清单](TASKS.md)；演示模式说明：[演示模式与扩展边界](PROTOTYPE_ARCHITECTURE.md)。

## 1. 产品目标

Clipline 是部署在 NAS 上的本地录像工作台。用户添加已有录像目录，系统建立文件与时间索引，再按真实时间回看、查找片段、截取和导出录像。耗时操作进入任务中心，处理过程和异常进入日志中心。

一期完成可靠的录像管理闭环；二期增加语音转写、画面内容识别及内容搜索。识别不是一期播放、索引或导出的前置条件。

### 1.1 已确定的需求

- NAS 使用 Docker 部署，同时支持 x86-64 和 ARM；本方案将 ARM 首发支持定义为 ARM64。
- 沿用旧版蓝色主题，主要强调色为 `#087bfa`，回看使用 UniFi 风格竖向时间轴。
- 录像源切换放在左侧 Logo 下方的下拉列表。
- 点击视频或片段后，在右侧显示片段详情。
- 同一回看状态只提供一个“管理片段”入口，避免重复按钮。
- 片段库保留录像源、日期、文件名和时间搜索，去掉编码筛选。
- 增加任务中心和独立日志中心，耗时操作提交后无需停留等待。
- 一期不实现语音和画面识别；详情、源配置、搜索、任务和设置保留二期位置。
- 本地真实录像测试使用操作者指定的宿主机目录，以只读方式提供给应用；实际路径仅保存于本地配置，新测试数据独立保存。

### 1.2 本方案的实现决策

落地基线为单容器内运行 API 和独立 Worker，SQLite 持久化索引、任务和业务日志，FFmpeg 负责媒体处理；一期默认依赖 CPU 软件处理，硬件加速作为可选能力。D1–D6 已完成运行基础、后台索引、真实回看、导出、运维与发布验收，历史证据见 [开发任务清单](TASKS.md)及其关联记录。

首发服务于单个 NAS 工作空间、可信局域网访问。32 位 ARM、公网服务、多用户权限、实时摄像机接入与跨录像源拼接不纳入一期。已完成 x86 NAS 实测与原生 Linux 双架构验收，其他设备的处理速度仍需实际测量。

## 3. 信息架构与界面规范

主导航：录像回看、片段库、任务中心、日志中心、录像源、设置。全局搜索只搜索一期录像信息。

| 区域 | 要求 |
| --- | --- |
| 左侧栏 | Logo 下方统一源切换；显示源状态；移动端采用抽屉 |
| 回看左区 | 日期、时段、缩放及竖向时间轴；较晚时间在上方 |
| 回看主区 | 播放器、当前源信息、当前时段片段条 |
| 回看右区 | 片段详情；窄屏改为可关闭的详情抽屉 |
| 区间管理 | 从唯一“管理片段”入口展开；与详情按需切换 |
| 二期占位 | 明确标为“二期预留”，使用静态说明，不呈现可点击的假功能 |

主题使用蓝色主操作、白色面板和浅灰背景。绿色仅用于成功或在线状态，不作为选中态、主按钮或时间轴强调色。编码继续作为片段元数据展示，不提供编码筛选。

空目录、无录像日期、无搜索结果、文件不可访问、任务排队和失败都应有明确提示。按钮支持键盘操作；模态窗口可关闭并正确恢复焦点；移动端不依赖悬停才能完成主要操作。

## 4. 一期功能需求

### 4.1 录像源

| 编号 | 需求 |
| --- | --- |
| SRC-01 | 选择服务端允许的录像根目录及子目录，或手动输入容器内路径；不得浏览任意系统目录 |
| SRC-02 | 自动建议名称，用户改名后不随路径变化覆盖；名称和目录均需校验 |
| SRC-03 | 校验真实目录存在、可读、位于允许根目录内；路径归一化后检查重复，阻止符号链接绕过边界；添加或编辑目录时提示父子目录重叠及关联源，明确确认后才允许新增重叠索引，同一目录仍禁止重复添加 |
| SRC-04 | 扫描频率支持 5、10、30 分钟和仅手动；新源使用已保存的默认频率 |
| SRC-05 | 默认勾选“添加后立即扫描”；保存后立即返回，扫描进入任务中心；未扫描源显示空态 |
| SRC-06 | 支持编辑名称、扫描频率和启停；停用阻止新扫描，不删除已索引录像及原文件 |
| SRC-07 | 支持手动扫描和最近扫描结果；同源重复扫描复用处理中任务 |
| SRC-08 | 添加和编辑表单保留自动语音转写、自动画面识别策略占位，默认关闭 |

目录属于容器内的 `/recordings` 挂载范围，界面应解释 NAS 路径与容器路径的映射。应用只读取原始录像，不修改、移动或删除录像文件。

建议一期将已有索引的源目录设为不可直接修改，提示添加新源；尚无索引时允许改目录。这样避免原有片段被错误关联到新目录中的同名文件。停用源的历史片段仍可回看和导出，前提是原文件可读。

### 4.2 扫描与时间索引

| 编号 | 需求 |
| --- | --- |
| IDX-01 | 首批支持 MP4、MKV、MOV、TS 文件的发现和探测；能否播放、快速导出由实际媒体参数决定 |
| IDX-02 | 保存文件名、大小、修改时间、真实起止时间、时长、编码、分辨率及可用状态 |
| IDX-03 | 优先从明确的文件名或目录时间规则推断开始时间；回退到文件时间时标明“估算时间”及来源 |
| IDX-04 | 跳过正在写入或近期更新的文件；文件稳定后由后续扫描补入，不用不完整文件生成可用片段 |
| IDX-05 | 增量扫描复用未变化文件；损坏文件单独记录原因，不使整个源扫描失败 |
| IDX-06 | 目录暂时离线或扫描取消时保留原索引；不能把一次读取失败当成文件全部消失 |
| IDX-07 | 索引重建重新检查元数据和时间规则，保留可复用的片段 ID，不删除原录像 |

录像时间以明确的时区解释，默认 `Asia/Shanghai`；持久化使用 UTC。跨日片段应出现在其覆盖的日期，不能只按文件开始日期筛选。

### 4.3 回看与片段详情

| 编号 | 需求 |
| --- | --- |
| REV-01 | 切换录像源、日期和时段时更新时间轴、片段条、播放器及详情，清除旧请求与旧播放位置 |
| REV-02 | 时间轴显示实际录像覆盖和断档；重叠文件不重复计算覆盖时长 |
| REV-03 | 点击录像覆盖定位对应片段与偏移；无录像位置显示断档，不伪造可播放内容 |
| REV-04 | 支持播放/暂停、进度定位、倍速、静音及全屏；无音轨时不影响回看 |
| REV-05 | 自动续播和跳过断档按保存设置生效；跳过时提示跨越的真实时间，不把间断当连续录像 |
| REV-06 | 浏览器不兼容的录像提交“播放准备”；显示任务状态，完成后播放缓存版本 |
| REV-07 | 点击视频、片段卡片或时间轴片段打开详情；详情同步显示当前片段 |
| REV-08 | 详情包含名称、源、起止时间、时长、编码、分辨率、大小、文件位置、时间来源和文件状态 |
| REV-09 | 详情可导出当前片段或进入时间轴截取；截取初始区间使用当前片段，自动续播不覆盖用户已编辑的区间 |
| REV-10 | 识别结果和事件时间点占位放在详情内；一期时间轴不显示识别占位块 |

### 4.4 片段库与搜索

| 编号 | 需求 |
| --- | --- |
| LIB-01 | 按录像源和日期筛选，关键词搜索文件名或录像起止时刻；无编码筛选 |
| LIB-02 | 关键词去除两端空白、忽略文件名大小写、将中文冒号转换为英文冒号 |
| LIB-03 | 时间搜索按本地起止时刻文本匹配，例如 `09:16:12` 可同时命中此刻结束和此刻开始的片段；不解释为时间区间查询 |
| LIB-04 | 支持网格/列表、分页、详情、回看跳转和当前片段导出；筛选变化时清除旧选择 |
| LIB-05 | 多选导出限定同一录像源、同一本地日期；对不符合条件的选择解释原因 |
| LIB-06 | 字幕搜索、画面标签、识别状态保持静态二期占位，不参与一期查询 |

### 4.5 截取与导出

| 编号 | 需求 |
| --- | --- |
| EXP-01 | 编辑起止时间或拖动时间轴边界；校验结束晚于开始、区间长度不超过设置上限且存在有效录像 |
| EXP-02 | 展示选择跨度、实际覆盖时长、断档和包含片段数；合并导出不能重复输出重叠录像 |
| EXP-03 | 快速模式优先复制编码，速度较快但切点受关键帧限制；参数不兼容时说明失败原因并支持精准重试 |
| EXP-04 | 精准模式执行必要转码，按目标边界裁剪；不把快速模式的近似切点称为精准 |
| EXP-05 | 多文件按时间顺序拼接；一期跳过无录像区间，不补黑帧、不生成不存在的录像 |
| EXP-06 | 提交后返回任务编号，用户可离开页面或关闭浏览器；完成后从任务中心下载真实结果 |
| EXP-07 | 输出文件须验证可读取、时长及音视频参数；失败或取消不提供半成品下载 |
| EXP-08 | 下载文件到期后标明已过期并允许重新提交；原始录像保持不变 |

一期区间导出限定同源、同一本地日期；跨日片段可以截取该日内的部分。片段库按勾选文件导出，不能自动把未选中的录像加入结果。“录像本身缺失”和“用户未选中”应分别提示。

### 4.6 任务中心

| 类型 | 触发入口 | 后台处理 | 完成结果 |
| --- | --- | --- | --- |
| 目录扫描 `scan` | 添加源、源页、任务中心、定时扫描 | 遍历、探测、增量索引、缩略图 | 新增/更新/跳过/失败统计 |
| 录像导出 `export` | 回看、详情、片段库 | 校验计划、裁剪、拼接、转码、验证 | 可下载文件、实际时长、过期时间 |
| 索引重建 `reindex` | 任务中心 | 重新检查文件和时间索引 | 修复统计及异常列表 |
| 播放准备 `prepare` | 不兼容片段、任务中心 | 生成播放代理及预览缓存 | 可播放地址或准备统计 |

| 编号 | 需求 |
| --- | --- |
| TSK-01 | 提交、排队、运行、完成、失败和取消均由服务端保存；不依赖打开网页 |
| TSK-02 | 展示类型、源、阶段、进度、提交时间、耗时和失败原因，支持状态与类型筛选 |
| TSK-03 | 排队任务可取消；运行任务显示取消处理中，确认停止后才显示已取消 |
| TSK-04 | 失败任务可重试，取消任务可重新提交；保留原任务记录和关联关系 |
| TSK-05 | 同源扫描与重建互斥，同片段相同规格的播放准备去重；重复请求不得启动重复处理 |
| TSK-06 | 容器重启后恢复排队任务，识别中断任务并按类型恢复或安全重做；最终文件不重复发布 |
| TSK-07 | 可跳到关联日志；日志详情可返回对应任务 |
| TSK-08 | 全局并行数可设置，另限制重型转码同时执行数，避免拖慢 NAS 和浏览查询 |
| TSK-09 | 语音转写、画面识别任务仅显示二期说明，不可创建 |

筛选、查看元数据、保存设置和读取已有播放文件直接响应，不创建顶层后台任务。缓存清理与到期文件清理属于系统维护，写日志即可，不刷满用户任务列表。

### 4.7 日志中心

| 编号 | 需求 |
| --- | --- |
| LOG-01 | 独立页面，显示时间、级别、类型、源、关联任务、标题和详情 |
| LOG-02 | 支持关键词、级别、类型、源和关联任务筛选，按新到旧分页 |
| LOG-03 | 记录任务入队、阶段切换、完成、失败、取消、重试和重启恢复，以及源和设置变更 |
| LOG-04 | 记录目录离线、文件探测失败、空间不足等异常；进度百分比不逐次写成业务日志 |
| LOG-05 | 可导出当前筛选的完整日志集合为 JSON；诊断包包含版本、架构、配置摘要、任务及日志，排除密钥等敏感字段 |
| LOG-06 | 明确保留期限，自动清理到期日志；业务事件与详细程序输出分开存储 |

### 4.8 设置

设置分类为基础、扫描、回看、导出、后台任务、识别与模型、关于。分类保存、撤销和恢复默认只影响当前分类；切换页面保留草稿，刷新丢弃未保存草稿。

| 设置 | 一期规则 | 建议初始值 |
| --- | --- | --- |
| 外观 | 浅色 / 深色 / 跟随系统；即时预览，保存后持久化，撤销恢复已保存值；覆盖页面、表单和弹窗，不改变录像色彩 | 跟随系统 |
| 新源扫描间隔 | 只影响之后添加的源，不覆盖已配置源 | 5 分钟 |
| 近期文件保护 | 自动与手动扫描都执行 | 30 秒，并检查文件稳定性 |
| 自动续播 / 跳过断档 | 关闭续播后保留断档偏好，但暂不应用 | 均开启 |
| 默认导出模式 | 应用于新提交的导出 | 快速 |
| 单次导出最大跨度 | 按选择跨度校验，不按覆盖时长绕过限制 | 最大 7 天；可选 10/30/60 分钟、6 小时、1/3/7 天 |
| 任务并行数 | 限制新开始任务，不打断已运行任务 | 2；可选 1/2/3 |
| 重型媒体并行数 | 导出转码与播放代理共享限额 | 1，系统设置可调 1/2/3 |
| 录像时区 | 基础设置可保存；已有源保留原索引时区，新源使用新时区 | Asia/Shanghai |
| 存储路径 | Docker 映射，界面只读 | `/recordings`、`/app/data` |
| 媒体线程数 | 后台任务设置可保存，新开始任务生效 | 2，可选 1–16 |
| 兼容播放 / 精准输出最大宽度 | 对新准备或新计划生效，快速模式保留原视频 | 1920 / 3840 |
| 导出保留 / 业务日志保留 | 系统设置可保存；已有导出的到期时间不变 | 24 小时 / 30 天 |
| 播放缓存上限 | 仅清理应用缓存，不触碰原录像 | 2 GiB，基础设置可调整，下一轮维护生效 |
| 识别与模型 | 展示二期能力、模型和运行设备占位 | 全部关闭 |

建议值是低资源部署的起点，正式发布前依据两类 NAS 的测试调整。配置变更须实际影响后端行为，不能只保存页面文案。

## 5. 二期预留要求

| 编号 / 扩展位置 | 预留内容 | 一期行为 |
| --- | --- | --- |
| P2-01 / `clip-detail` | 字幕、识别标签、事件时间点、手动分析 | 详情静态说明 |
| P2-02 / `source-settings` | 手动/扫描后自动转写和识别策略 | 添加、编辑表单静态说明；默认 false |
| P2-03 / `library-filters` | 字幕、标签、识别状态筛选 | 静态说明，不可查询 |
| P2-04 / `search-provider` | 内容和语义检索 | 全局搜索扩展位置 |
| P2-05 / `task-type` | 转写、视觉分析、模型准备任务 | 任务中心静态说明 |
| P2-06 / `settings-section` | 模型、设备、缓存和资源预算 | 识别与模型分类静态说明 |
| P2-07 / `timeline-track` | 根据真实识别结果定位事件 | 仅代码插槽，一期不显示 |

识别结果通过稳定片段 ID 关联，事件偏移使用片段内毫秒；不改写基础录像覆盖。结果记录模型、版本、时间和置信度。识别失败不能影响原有扫描、回看和导出。

一期镜像不包含模型文件及 ASR/视觉运行依赖，启动不下载模型、不探测识别设备。二期增加独立 provider 与 Worker 能力；单纯打开开关不代表完成识别。

## 6. 非功能要求

| 编号 | 要求 |
| --- | --- |
| NFR-01 | `linux/amd64`、`linux/arm64` 使用同一版本镜像标签；两者均完成实际扫描、回看、精准导出和任务恢复测试 |
| NFR-02 | 原录像只读挂载；配置、数据库、缩略图、缓存和导出写入独立可写持久化目录 |
| NFR-03 | SQLite 数据库使用 NAS 主机本地文件系统，不能部署在 SMB/NFS 共享目录 |
| NFR-04 | 普通查询不触发同步转码；媒体处理有并行、超时与缓存上限，等待期间界面可继续操作 |
| NFR-05 | 任务与日志可恢复，文件结果经过验证，取消、重试和重复请求不会破坏索引或原文件 |
| NFR-06 | 目录、文件和输出名由服务端校验；FFmpeg 参数不通过 shell 拼接执行 |
| NFR-07 | 不依赖特定显卡或厂商设备；硬件加速缺失时两种架构仍有软件处理路径 |
| NFR-08 | 提供健康检查、版本和架构信息、备份与升级说明；升级前备份，迁移失败不得继续启动 |

性能测试使用明确的参考硬件与数据集记录结果，不承诺所有 ARM 设备转码实时。建议以 10 万条索引测试分页查询和时间轴聚合，目标为正常负载下常用查询与任务提交约 1 秒内返回；这是待实测的发布目标。

## 7. 主要流程验收

| 验收编号 | 操作 | 合格条件 |
| --- | --- | --- |
| AC-01 | 挂载目录，添加新源并勾选首次扫描 | 立即得到源与任务；后台产生真实索引，未扫描时为空态 |
| AC-02 | 添加重复路径、越界路径、越界符号链接及不可读目录 | 服务端拒绝并说明原因，不产生错误源或扫描任务 |
| AC-03 | 连续切换两个源和两个日期，再点时间轴 | 视频、偏移、片段条、详情全部对应当前选择，无旧画面覆盖新结果 |
| AC-04 | 回看含断档、重叠和跨日的样本 | 覆盖正确、断档可见、无重复覆盖，跨日两天都能查询 |
| AC-05 | 点击视频和卡片，转入截取 | 详情同步；区间初始化正确；唯一管理入口；二期占位在详情 |
| AC-06 | 片段库搜索文件名、英文/中文冒号时间，切换筛选 | 结果遵守文本匹配规则，旧选择清除，无编码筛选和识别查询 |
| AC-07 | 对多段含断档录像进行精准导出 | 输出为真实裁剪文件，只包含有效选中内容，时长与计划一致，原文件校验值不变 |
| AC-08 | 快速模式遇到不兼容参数 | 明确失败，允许创建关联精准重试任务，不静默扩大转码负载 |
| AC-09 | 同时提交任务，再关闭网页 | 服务端继续执行；重新打开可查询完成结果并下载 |
| AC-10 | 排队取消、运行取消、失败重试；处理期间重启容器 | 状态准确、停止子进程、保留历史、恢复安全；没有重复发布与半成品下载 |
| AC-11 | 修改两类设置，仅保存其中一类 | 只保存当前类，另一类草稿保留；后端使用保存值并记录变更 |
| AC-12 | 从任务查看日志，筛选后导出，再从日志返回任务 | 正确关联；导出包含筛选全部结果而非当前一页 |
| AC-13 | NAS 目录离线、损坏文件、持续写入文件、磁盘不足 | 错误有日志；其余查询仍可用；既有索引不被误清空 |
| AC-14 | 在 amd64 与 arm64 各运行完整媒体流程 | 都通过软件处理路径；有独立运行记录，构建成功不替代运行验收 |
| AC-15 | 检查所有二期区域和一期镜像启动 | 只有占位，无识别请求、模型依赖、自动模型下载或识别演示结果 |

精准导出在固定帧率测试样本上的边界误差目标不超过一个输出视频帧；AAC 等音频封装可有编码填充，按输出时间戳校验，不能仅比较播放器显示的整秒时长。

## 8. 开发交付顺序

1. 建立双架构运行环境、数据库迁移、目录边界和基础 API。
2. 实现持久化任务、真实扫描、增量索引及业务日志。
3. 接通源切换、时间轴、详情、片段库和真实播放；实现播放准备。
4. 实现快速/精准导出、结果下载、取消、重试和重启恢复。
5. 接通设置、日志导出、清理策略和诊断；完成双架构验收与部署说明。
6. 一期稳定后再实施二期 provider、模型与内容搜索，保持原有流程独立可用。

阶段完成以验收结果为准。当前硬件和真实录像格式尚未完整提供，开发文档给出可执行基线，性能与硬件加速范围留待实测，不阻塞基础功能开发。
