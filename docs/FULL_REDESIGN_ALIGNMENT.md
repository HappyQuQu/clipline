# Clipline Full Redesign 对齐与开发方案

状态：开发基准
更新时间：2026-07-31
适用范围：Web 前端、前后端联调、产品验收、视觉验收

执行任务见 `docs/FULL_REDESIGN_TASKS.md`。任务清单包含 47 个可验收任务、依赖顺序、涉及文件和逐页完成条件。

## 1. 基准与优先级

本轮开发必须以 `frontend/prototypes/clipline-full-redesign` 为唯一视觉和交互基准。

当仓库内容发生冲突时，按以下顺序处理：

1. full redesign 原型的可见布局、文案、组件结构、状态和交互。
2. 本文档定义的业务边界、响应式修复和验收规则。
3. `docs/PRD.md`、`docs/UI_FLOW.md`、`docs/MVP_SCOPE.md` 与 `docs/TECH_DESIGN.md`。
4. 当前 `frontend/src` 实现；它只提供真实数据和业务能力，不作为设计依据。

允许偏离原型的情况只有三类：

- 将原型中的模拟数据替换为真实 API 数据。
- 补齐加载、空、错误、禁用、权限或超长内容等原型未覆盖状态。
- 修复已确认的响应式、可访问性或浏览器布局故障。

任何偏离都不得改变页面信息架构、视觉层级、组件位置、密度、色彩、字体、圆角、可见文案和核心操作路径。

## 2. 产品边界

Clipline 是部署在 NAS 或家庭服务器上的录像文件工作台，不是实时 NVR 或摄像头控制平台。

核心闭环：

```text
添加录像目录
→ 扫描并建立索引
→ 按真实时间回看
→ 使用字幕或视觉标签查找内容
→ 创建语音、视觉或导出任务
→ 在任务中心查看结果并下载
```

界面统一使用“录像源、目录、扫描、索引、片段、回看、识别、导出”等语言。不得引入 RTSP、直播、在线状态、码流、延迟或录像计划等实时摄像头语义。

## 3. 信息架构

### 3.1 全局框架

- 顶栏：Logo、全局字幕搜索、快捷键提示、通知、账户。
- 一级导航：回看、片段库、任务、管理。
- 全局搜索为顶栏浮层，不是独立一级页面。
- 管理包含录像源、活动日志、设置。
- 设置包含概览、扫描与索引、导出、识别与任务、模型管理、日志与诊断、关于。

Clipline
├── 回看
├── 片段库
├── 任务
└── 管理
    ├── 录像源
    ├── 活动日志

        ├── 导出
        ├── 识别与任务

        ├── 日志与诊断

| 片段库 | 筛选、批量选择和处理片段 | 页头操作、横向筛选栏、网格/列表切换、稳定详情栏、底部批量操作条 |

## 4. 页面与交互规范

### 4.1 回看

- 左侧上下文栏显示当前录像源、目录、启用状态、片段数、最近扫描、日期和显示范围。
- 主播放器是页面第一视觉层级；播放器控制条覆盖在视频底部。
- 时间线只展示真实录像片段和断档，不增加虚构事件轨。
- 时间线保留上一片段、下一片段、缩放、日期、播放头、录像图例和断档数。
- 选中区间必须同时显示起止时间、时长和断档提示。
- 快速/精准模式与“导出区间”按钮位于同一操作层。
- 下方片段条展示缩略图、真实时间、时长和识别状态。
- “识别字幕”和“导出区间”是片段区的主要操作。
- 导出确认使用原型弹窗；创建成功后可进入任务页或继续浏览。

### 4.2 片段库

- 标题统一为“片段库”，不再使用“片段墙”作为导航名称。
- 筛选栏包含搜索、录像源、识别状态、日期、网格/列表切换。
- 默认三列网格；卡片展示缩略图、开始时间、范围、时长和识别状态。
- 选中卡片以蓝色描边和左上选择标记表达。
- 桌面端右侧详情栏稳定存在，包含预览、基础信息、语音识别、视觉识别和导出。
- 多选后底部出现固定批量操作条，显示数量、取消、视觉识别和合并导出。

### 4.3 任务

- 标题统一为“任务”，不再使用“任务中心”作为导航名称。
- 导出、语音识别和视觉识别共用一张任务表。
- 状态筛选为：全部、进行中、待处理、已完成、失败。
- 表格列为：任务、类型、来源、状态、结果/进度、更多操作。
- 已完成导出必须提供浏览器下载动作。
- 页面底部保留处理中、识别完成、需要处理三张摘要卡。

### 4.4 管理 / 录像源

- 录像源、活动日志和设置只出现在“管理”二级导航中。
- 源列表字段为录像源、目录路径、状态、片段/错误、最后扫描和更多操作。
- 选中源详情由左侧最近片段预览和右侧配置组成。
- 配置项包括显示名称、扫描方式、目录路径、语音识别策略、视觉识别策略。
- 目录安全文案必须明确：Clipline 仅读取目录并建立索引，不改写或删除源视频。
- 危险操作、立即扫描和保存更改放在详情底部。

### 4.5 管理 / 活动日志

- 仅展示真实可追溯事件：扫描、导出、语音识别、视觉识别和文件失败。
- 筛选包含关键词、类型、录像源和日期。
- 表格列为时间、类型、事件、录像源、详情。
- 日志页面必须使用完整管理内容宽度。

### 4.6 管理 / 设置

- 全局设置与单源覆盖项必须明确区分。
- 概览保留系统状态、索引内容、媒体工具、后台任务健康条。
- 概览保留存储路径和缓存占用两张信息卡。
- 导出设置中的 `data/exports` 是只读服务端暂存目录；用户下载位置由浏览器决定。
- 模型管理单独成页，支持语音模型筛选、下载、进度、删除和使用中状态。
- 当前使用中的语音模型不可删除。
- 视觉模型只展示状态和重新加载，不暗示存在未实现的下载 API。
- 可编辑设置页使用底部粘性操作条，包含恢复默认值、保存更改和保存反馈。

## 6. 响应式与可访问性底线

### 6.1 响应式

- `>1180px`：完整桌面布局。
- `901–1180px`：收窄回看上下文栏、片段库两列、隐藏次要表格列。
- `661–900px`：回看上下文栏移至顶部；片段库隐藏右侧详情；管理侧栏收窄。
- `<=660px`：一级导航改为底部导航；管理二级导航改为顶部横向导航；表单与卡片单列。
- 窄屏允许数据表内部横向滚动，但页面本身不得出现无意义横向溢出。

已确认的原型缺陷：

- 当前活动日志页在一次实机捕获中错误收缩到左侧约 306px，右侧出现大面积空白。
- 正式实现必须保证日志内容占满 `.manage-content`，并在窄屏时仅让 `.logs-table` 内部滚动。
- 这是布局修复，不是重新设计。

### 6.2 可访问性

- 所有可操作元素必须是语义化 `button`、`input`、`select` 或链接。
- 仅图标按钮必须有可访问名称和 tooltip。
- 键盘焦点必须使用原型蓝色焦点环，不能移除。
- 状态不能只依赖颜色；必须同时有文字或图标。
- 动态任务进度、保存结果和错误提示需要可被辅助技术感知。
- 点击目标桌面端不小于 36px，移动端不小于 44px。
- 需要实际验证键盘顺序、读屏名称、对比度和 `prefers-reduced-motion`。

## 8. 调整实施方案

### Phase 0：冻结基准

- 将本文件和原型截图作为需求与视觉验收基准。
- 记录每个页面的基准 viewport、关键状态和所需真实 API。
- 禁止在对齐期间新增风格、模块或导航入口。

完成标准：团队对信息架构、术语、页面清单和允许偏离范围没有歧义。

### Phase 1：应用骨架与设计 token

- 将 `App.tsx` 的一级导航收敛为回看、片段库、任务、管理。
- 将搜索从独立 view 改为顶栏搜索浮层。
- 建立原型 token、顶栏、一级导航、页头、按钮、输入、筛选、状态 badge 和 toast。
- 将来源、日志、设置挂入统一 `ManagePage`。

完成标准：四个一级入口、三个管理二级入口和七个设置分类的层级与原型完全一致。

### Phase 2：回看核心闭环

- 按原型重组源上下文、播放器、时间线、区间选择和片段横条。
- 接回现有视频播放、真实时间映射、前后片段、缩放、断档和导出逻辑。
- 实现原型导出弹窗和任务创建成功状态。

完成标准：同一数据状态下，与原型 1440px 截图做并排对比，无 P0/P1 视觉差异。

### Phase 3：片段库与任务

- 片段库完成网格/列表、筛选、选中详情、多选批量条和识别/导出动作。
- 任务页统一导出、语音和视觉任务的字段、状态、进度、失败原因和下载动作。
- 保留真实 API 状态枚举，通过展示映射适配原型文案。

完成标准：单选、多选、任务进行中、完成、失败和下载状态全部可操作。

### Phase 4：管理与设置

- 按原型实现录像源表格与选中源详情。
- 将活动日志改为紧凑表格并修复内容宽度问题。
- 按七个分类迁移现有设置能力；保留真实保存、模型下载/删除、视觉模型重载和诊断逻辑。
- 校正 Web 导出语义：只读服务端暂存路径 + 浏览器下载。

完成标准：管理导航不重复；全局默认和单源覆盖关系清晰；所有真实后端能力都有对应入口。

### Phase 5：状态、响应式与无障碍

- 为每页补齐 loading、empty、error、disabled、offline/unavailable 和长文本状态。
- 在 1440、1180、900、660、390px 验证布局。
- 验证键盘导航、焦点、读屏名称、状态通知、对比度和减少动态效果。
- 修复日志页窄宽异常和所有页面级横向溢出。

完成标准：核心任务在 390–1440px 可完成；不存在遮挡、裁切、错误换行或不可达操作。

### Phase 6：视觉回归与发布

- 对每个页面使用相同 viewport 和相同业务状态分别截取原型与正式实现。
- 先比较整体骨架，再比较字体、间距、颜色、边框、圆角、图片裁切和控件状态。
- 每轮修复后重新截图，直到 P0/P1 差异清零。
- 运行前端构建、类型检查和关键交互测试。

完成标准：不以“风格接近”验收；必须逐页、逐状态与原型一致。
